Q4 Systems Architecture & Security Spec

Architecture #security #gemini-3
Gemini 3 Assistant Click an action to preview:

Gemini Notes v0.4.0-beta combines a native macOS Electron architecture with context-isolated sandboxing, local Personal Knowledge Base RAG, and Gemini 3 REST integration.

  • Header-Only API Auth: All Gemini requests authenticate via x-goog-api-key HTTP headers—never URL query strings.
  • Hardened Local Vault: Notes, settings, and KB indexes use atomic writes with 0o600 owner-only permissions inside a 0o700 directory.
  • Strict CSP: Disables remote image beacons and Chromium localStorage credential mirroring.

Security & Local Privacy

Strict boundaries across IPC handlers, Gemini REST authentication, local file permissions, offline PDF rendering, and HTML sanitization.

Layer 01

Strict CSP & XSS Sanitizer

Content Security Policy restricts images to 'self' data: blob: to block external tracking beacons, while src/services/sanitizer.ts scrubs unsafe tags, styles, and scripts on every AI response and paste event.

Layer 02

Sender-Verified IPC & Header Auth

All 15 Electron IPC handlers validate event.senderFrame.url. Gemini API calls authenticate via the x-goog-api-key HTTP header with no Chromium localStorage credential mirroring.

Layer 03

Atomic 0o600 Vault & Process Isolation

Notes, settings, and Knowledge Base files live in a 0o700 owner-only folder with atomic 0o600 writes, isolated subprocess environments for PDF/doc extraction, and offline sandboxed PDF export.
